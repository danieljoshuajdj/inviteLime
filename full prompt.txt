# 4. ARCHITECTURAL PRINCIPLE

There must be:

```text
ONE APPLICATION
ONE DATABASE
ONE CUSTOMER SYSTEM
ONE ADMIN SYSTEM
ONE TEMPLATE RUNTIME
MANY TEMPLATES
MANY CUSTOMER INVITATIONS
MANY UNIQUE PUBLIC URLS
```

Do NOT create:

```text
one React application per template
one deployment per template
one website per customer
one database per customer
```

A template is data/content loaded by the platform.

A customer invitation is a database record referencing a template version.

# 5. TEMPLATE ARCHITECTURE

Templates are independent normalized HTML/CSS/JS packages.

Canonical structure:

```text

├── index.html
├── manifest.json
└── assets/
```

Templates may contain their own:

* HTML
* CSS
* JavaScript
* animations
* transitions
* GSAP
* SVG
* canvas
* WebGL where appropriate
* audio
* video
* custom fonts

Do not reject a template merely because it contains JavaScript.

Instead, execute it in an isolated/controlled runtime.
